# 보관 증권 구조의 재처리

피보험자 값에 이름과 식별용 부가 필드가 함께 있으면 전체 문자열 비교가 가입 근거 연결을
누락했다. 완전한 이름을 기존 구성원과 비교하고, 남은 문자열 전체가 달력상 유효한 날짜
또는 정해진 마스킹 형식 하나와 선택적 성별·나이 필드로 구성되는지 검사한다. 괄호·공백·
슬래시 구분을 허용하되 중첩/미완성 괄호·중복 필드·알 수 없는 문구는 거부한다. 파싱한
부가 정보를 저장하거나 회원 별칭으로 추가하지 않는다. 원래 피보험자 필드 전체의 위치를
근거로 유지한다.

이름(마스킹 식별번호) / 나이 / 성별 / (등급) 설명 형식은 완전한 이름 하위 필드를 직접
대조한다. 자유 형식 등급 설명을 새 신원 근거로 쓰지 않으며, 설명에 다른 회원명·추가
식별번호/날짜·개인 필드가 있으면 거부한다. 띄어 쓴 한국어 개인 필드도 거부한다. 표 셀의
줄 경계는 유지하며 새 설명 허용 분기는 여러 줄 레코드를 받지 않는다. 단순 이름의 기존
공백 정규화는 유지한다. 구성원 중복·다른 대상자와 안전하지 않은 표/열 경계는 그대로 제한한다.

0065는 종료된 작업의 새 처리 버전을 추가하며 API/Worker schema fence를 함께 갱신한다.
`RetainedPolicyRepository.enqueue`와 선택한 ID만 소비하는 `RetainedPolicyJobQueue`를 기존
범위 runner에 연결한다. 기존 원문·추출·완료 범위·사용자 교정을 보존하고 현재 원문 세대를
고정한다. 기본 queue는 이 작업을 claim하거나 복구하지 않는다. 준비·lease·예산·저장·API
반영에서 오래된 세대를 거부하고, 문서별 예산과 교정 권위를 유지한다. 보호 자료 전환과
전체 재처리 수용은 별도로 진행한다.

전송 전 보호 검사에서 label과 떨어진 원문 조각의 마스킹 식별번호를 발견해 실제 요청을
차단했다. 외부 HTTP/provider 호출은 0건이고 기존 행 보존을 확인했다. 최소화 v3는 두
최소화 경로에서 식별번호 형식을 label 없이도 제거한다. 0066은 retained v2와 공유 privacy
digest를 갱신해 과거 작업/입력을 보존하면서 새 입력으로 처리한다. 기존 provider/약관/검수
작업 또는 retained v2 이력이 있는 경우 downgrade를 보수적으로 거부한다.
