## B08에 남기는 측정·릴리스 항목

- 고정 평가셋 `fixtures/synthetic/claim-guidance/cases.v1.json`: dev/holdout 각 10, 후보 pool 48, 관련 정답 19, 무관 사건 6. recall/primary/conditional ≥0.90, unrelated/hold ≤0.05를 변경하지 않는다. 후보 scorer는 금액·근거·원문 처리 정확도를 채점하지 않는다.
- 지원 범위: 제공 전체 문서/가입 담보를 분모로 해석·설명·실행을 따로 집계한다. 미지원/미연결/모순을 제거하지 않는다. 상위 k·전체 출력량·오류 범주·필수 질문/클릭 수가 별도로 필요하다.
- 기존 시간 측정은 1계약/2담보/2조항/2판본 ASGI/PG 42요청, 최초 1쌍 + warm 10쌍 + 무관 Worker 행 잠금 10쌍이다. B04 `a9f904d` 기록의 POST p95 유휴 1045.411ms/행 잠금 중 1128.514ms는 해당 환경 결과다. DB 캐시를 비우지 않았고 실제 gateway·대표 전체 자료·CPU/OCR/import/검수 경쟁·RSS/idle 측정은 아니다. 신규 실측 없이 최신 head 성능 PASS로 옮기지 않는다.
- 실제 모델 순효과는 아직 미측정이다. 합성 제안/실제 SDK MockTransport 통과를 real-model accuracy/cost로 표시하지 않는다. 개발/holdout 구분과 동일 입력의 baseline/local/review 비교를 유지한다.
- 기존 Playwright는 API mock이며 실패 screenshot/trace를 저장한다. BASE_URL 변경만으로 실제 backend E2E가 되지 않는다. 위 보호 Chromium 결과는 민감 artifact를 남기지 않은 별도 실제 API 실행이다. 제한된 저장 결과 조회를 전체 새 사건→검수→청구 준비의 browser E2E로 확대하지 않는다. Windows/모바일은 미검증이며 서버 연결 없는 완전 오프라인은 Local-first 수용 범위가 아니다.
- 버전 준비는 기존 5개 API/Worker/Web metadata, 두 editable `uv.lock` 항목, OpenAPI health/default, health 테스트와 CHANGELOG/README/로드맵을 동기화한다. 기존 `scripts/release_audit.py --version 0.5.0 --commit-sha <full-sha>`와 `.github/workflows/release.yml`, `verify_release_images.py`, `release_notes.py`, `release_compose_smoke.py`를 재사용한다. 0064/knowledge generation/이미지 digest/정확한 소스를 연결한다. 이 문서는 버전·코드·계약·CI를 수정하지 않으며 release/activation/deployment 완료 증거가 아니다.
