# Event and Result PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Complete — PR #21 merged as `ba3447245c5569de043433a53a59a0e493a0d628`; v2
private-knowledge results and assistance were added later without changing the app-shell-only cache boundary.

**Goal:** Provide a mobile-first flow from a short pre-visit situation or detailed post-treatment receipt lines to evidence-backed, action-first results without requiring optional questions and without storing medical data in persistent browser storage.

**Architecture:** The Worker reuses the provider-neutral AI boundary to structure a bounded natural-language situation into non-authoritative fact candidates. A dedicated PostgreSQL event-structuring queue keeps that work separate from PDF jobs; the API persists the user text, candidate facts, conflicts, and audit versions but owns no provider calls. The Web owns event drafting, editable AI facts, manual receipt-line input, result presentation, Evidence disclosure, and navigation to ClaimCase creation. The deterministic API engine alone owns tri-state evaluation, calculations, versioning, and stale detection. A failed structuring job never prevents manual analysis. The Web uses generated OpenAPI types, a no-store fetch boundary, and the memory-only query cache introduced by the policy-candidate Web plan.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Vite PWA 1, Vitest 4, Testing Library, Playwright Chromium, Python 3.14, FastAPI, direct psycopg, PostgreSQL 18, Alembic, the provider-neutral OpenAI Responses adapter from Plan 005, and generated OpenAPI/JSON Schema types.

**Spec:** `docs/design/event-result-pwa.md`, `docs/design/coverage-decision-engine.md`, `docs/design/v0.1-product.md`, `docs/design/claim-workflow.md`, and `docs/plan/003-v0.1-implementation-index.md`

## Global Constraints

- Branch: `feat/event-result-pwa`; commits use Conventional Commits and stay under 72 characters.
- Only wholly synthetic members, events, facts, receipt lines, Riders, rules, Evidence, and provider responses may enter Git, tests, logs, screenshots, or CI artifacts.
- The Web never stores diagnosis files, receipt images, prescription files, OCR output, PDF data, Evidence text, event results, claim amounts, or user notes in localStorage, sessionStorage, IndexedDB, URL query strings, service-worker caches, or persistent drafts.
- Unsaved event input is React memory state only. A reload or session expiry discards the unsaved draft; a server-saved MedicalEvent can be fetched again after login.
- Natural-language structuring is an optional AI job. AI may normalize facts and produce questions but never returns or decides `MATCH`, `NO_MATCH`, `UNKNOWN`, or a monetary result.
- The UI displays exactly the decision vocabulary `MATCH`, `NO_MATCH`, and `UNKNOWN` in technical status labels, but user-facing copy uses `청구 검토`, `조건 불일치`, and `추가 확인 필요`; it never says `지급 확정` or promises payment.
- Missing facts, stale Evidence, unknown renewal state, unsupported rules, and partial calculations remain `UNKNOWN` or a visible hold reason; the UI never converts them to zero or `NO_MATCH`.
- Receipt amounts are decimal strings with an explicit currency; JavaScript floating-point arithmetic is not used for benefit amounts.
- API and Evidence requests use `credentials: "include"`, `cache: "no-store"`, and server `Cache-Control: no-store`. The Web query cache remains memory-only and is cleared on logout, 401, and session expiry.
- The service worker precaches only hashed static app-shell assets. No runtime cache rule may match `/api/`, `/documents/`, `/evidence/`, `/medical-events/`, `/claims/`, or any result payload.
- Route paths use `/app/...` so they are not intercepted by the current Nginx reserved `/claims` and `/policies` locations. The private-runtime plan must proxy `/api/` through the Web gateway to the internal API service.
- Component tests use fake fetch responses and synthetic fixtures. Playwright tests use one Chromium worker and never call OpenAI, Google Drive, an insurer, or a private document path.
- Windows browser installation, real mobile PWA installation, Tailscale access, actual documents, and production ingress remain explicitly unverified.

## Shared API and View Interfaces

The event and result plans must provide these generated operation shapes. The exact wire types come from `apps/web/src/api/generated.ts`; the following fields define the Web behavior and use decimal strings for money.

```ts
export type EventMode = "pre_visit" | "post_treatment";
export type FactState = "confirmed" | "ambiguous" | "missing" | "conflict";

export interface MedicalEventFact {
  fact_id: string;
  field_id:
    | "event_date"
    | "visit_date"
    | "condition_class"
    | "diagnosis_label"
    | "treatment_kind"
    | "admission"
    | "outpatient"
    | "pharmacy";
  value: string | boolean | null;
  source: "user" | "ai" | "system";
  state: FactState;
  evidence_ids: string[];
}

export interface ReceiptLine {
  receipt_line_id: string;
  category: "outpatient" | "inpatient" | "pharmacy";
  benefit_category: "covered" | "possibly_excluded" | "unknown";
  amount: string;
  currency: string;
  coverage_status: "confirmed" | "unconfirmed";
}

export interface MedicalEvent {
  event_id: string;
  family_member_id: string;
  version: number;
  mode: EventMode;
  situation: string;
  facts: MedicalEventFact[];
  receipt_lines: ReceiptLine[];
  event_date: string | null;
  visit_date: string | null;
}

export interface EventResult {
  event_id: string;
  event_version: number;
  generated_at: string;
  policy_snapshot_version: string;
  rule_set_version: string;
  engine_version: string;
  stale: boolean;
  groups: {
    claim_review: ClaimCandidateView[];
    needs_information: ClaimCandidateView[];
    mismatch: ClaimCandidateView[];
  };
  partial_failures: Array<{ rider_id: string; reason_code: string }>;
}

export interface ClaimCandidateView {
  rider_id: string;
  rider_label: string;
  result: "MATCH" | "NO_MATCH" | "UNKNOWN";
  hold_reasons: string[];
  missing_facts: string[];
  conditional_estimate: {
    currency: string;
    confirmed_amount: string;
    additional_amount: string;
    excluded_amount: string;
    exclusion_reasons: string[];
  } | null;
  required_documents: string[];
  evidence_ids: string[];
}
```

The API operations consumed by the Web are:

```text
POST  /api/v1/medical-events
GET   /api/v1/medical-events/{event_id}
PATCH /api/v1/medical-events/{event_id}                 # expected_version required
POST  /api/v1/medical-events/{event_id}/structure
POST  /api/v1/medical-events/{event_id}/analyze
GET   /api/v1/medical-events/{event_id}/results/{version}
GET   /api/v1/evidence/{evidence_id}
```

Plan 008 owns create, patch, deterministic analyze, and versioned results. Task 1 of this plan adds the read projection and the separate asynchronous structuring operation, then regenerates OpenAPI before Web client work. The Web consumes only those generated operations and never hand-writes substitute wire types.

Structuring returns an asynchronous job projection and must be polled through its generated status URL. Deterministic analysis returns the completed versioned result synchronously; the Web must not invent a second polling contract or treat the structuring `202` response as a decision result.
