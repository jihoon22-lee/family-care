# v0.5 local-first claim guidance

- 상태: B01~B05 통합, B06 구현 중; 전체 제품 수용은 #60/#70에서 별도 확인
- 기준: [요구사항 #60](https://github.com/jihoon22-lee/family-care/issues/60)
- 개인정보·인증·가정 범위·CSRF·암호화·민감정보 비캐시·교정/청구 이력 보존은 기존 설계를 따른다.

## Result meaning

외부 AI 없이 문서상 가입한 담보에서 사건 관련 후보를 찾고, 지급 확정과 구분해 문서 기준
예상액·계산식·필요한 사건 사실을 제공한다. 확인된 상태를 만들지 않고 결과 snapshot에
문서 유지 가정을 기록한다. 현재 상태보다 사건일 적용 근거를 먼저 평가한다.

가입/대상/판본의 결정적 반대 증거는 무시하지 않는다. 규칙의 개별 tri-state는 보존하되
최신성·처리 상태 하나로 모든 후보·금액을 지우지 않는다. 관련성 근거가 없는 담보를
조건부 목록에 넣어 후보 수를 채우지 않는다. 지원하지 않는 조건은 해당 조건만 제한한다.

## Architecture and compatibility

기존 `KnowledgeCoverageContext`, `PolicySnapshot`, allowlist DSL과 Decimal 계산을 재사용한다.
버전 있는 local guidance snapshot을 기존 decision run에 연결하고 과거 v1/v2 결과는 그대로 읽는다.
새 응답은 후보 그룹·원래 출처를 포함한 공통 담보 참조·문서상 가입·상태 가정·조건·계산 준비·
근거·지식/규칙/사건/가정 revision을 구분한다. 각 축을 다시 전역 승인 gate로 조합하지 않는다.

Web은 생성된 응답 타입을 소비하며 후보/금액을 다시 판정하지 않는다. API는 가정과 설명을
만들고 Worker는 원문에서 구조화된 지식을 생성한다. 지원되는 한 문서 사례부터 실제 API와
소비자를 연결하고 이후 WP에서 operational/private adapter와 자동 연결을 확장한다.

B01의 HTTP 계약은 기존 `CoverageDecisionResponse` v2에 optional `local_guidance`를
추가한다. 내부 안내 schema version은 `1`이며 `decision_runs.local_guidance_json`에
이벤트·가정 범위·버전과 함께 저장한다. 생성 JSON Schema/OpenAPI/TypeScript가 같은 모델을
소비하며 과거 응답의 새 필드는 null이다. 구결과를 새 의미로 다시 계산하지 않는다.

조건부 예상액은 확정 지급액이 아니다. 문서 유지 가정과 남은 조건, 계산식과 근거를 함께
보관한다. `POINT`, `RANGE`, `FORMULA`, `UNAVAILABLE`은 계산 준비를 표현하며 후보 그룹과
독립적이다. B01은 검증된 단일 산식부터 연결하고 범위·복수 계약 합산은 WP06에서 확장한다.

## Calculations and questions

계산 publication과 실제 필수 입력이 있는 경우에만 금액을 산출한다. 가입금액·한도는
산식 없이 지급액이 될 수 없다. 입력이 부족하면 근거 있는 식과 필요한 입력을 유지한다.
횟수 기록이 없다는 이유로 지급 0회를 만들지 않는다. 비용·진단·수술 사실을 가정으로 만들지 않는다.
추가 질문은 답을 바꾸는 사건 사실에 한정하고 내부 문서 연결·최신성 확인을 기본 업무로 전가하지 않는다.

## AI and failure isolation

기본 analyze는 로컬 처리와 저장만 하며 외부 AI 작업을 자동 예약하지 않는다.
추가 검수는 명시적 요청으로 별도 job을 생성한다. 늦은 검수/장애/미설정은 로컬 snapshot을
덮거나 지우지 않는다. 실제 외부 전송은 별도 승인된 최소화 범위를 따른다.

B05의 `POST /medical-events/{id}/guidance-reviews`는 저장된 run과 사건 버전만 받는다.
가정·가입 담보 index·원문·규칙·입력·privacy/model/prompt revision은 서버에서 묶는다.
`GET /guidance-reviews/{id}`와 `POST /guidance-reviews/{id}/cancel`은 같은 인증·가정 범위와
no-store 경계를 따른다. 동일 입력의 실패·취소·완료 작업도 재사용하며 불명확한 전송을
자동 재시도하지 않는다. 기본 분석과 최초 문서 구조화의 작업은 이 검수와 별개다.

Worker의 `FAMILYCARE_ENABLE_GUIDANCE_REVIEW=false`는 선택 검수 실행을 끈다.
API의 `FAMILYCARE_GUIDANCE_REVIEW_MODEL`은 요청의 모델을 고정하고, key는 Worker의 기존
`OPENAI_API_KEY`만 사용한다. 미설정·비활성 작업은 전송 없이 실패 상태가 된다.
검수당 최대 2회, 호출당 보수적 입력 32,768/출력 4,000 token, 총 65,536/8,000 token을
예약한다. 현재 runner는 독립 원문 탐색과 로컬 답변 대조를 한 요청으로 수행한다.
SDK retry는 0, 호출은 최대 40초, 작업은 100초다. 정책/약관 구조화와 일일·문서별 예산을
공유하므로 세 Worker 예약 reader를 함께 갱신한다. 알 수 없는 사용량은 0으로 표시하지 않는다.

원문 인용과 해석을 API가 재검증한 뒤 별도 review publication을 만들어 같은 로컬 엔진으로
재평가한다. AI의 숫자는 지급액 필드로 복사하지 않는다. 결과는 원래 run이나 전역 지식을
덮지 않는 별도 snapshot이며, 원문 미제공과 해석 미검증을 구분한 부분 범위·차이·근거를
함께 반환한다. 검수 전용 근거는 기존 run의 청구 snapshot으로 섞지 않는다.
취소·입력 변경·기한 만료는 전송 직전과 결과 게시 전에 확인한다. 이미 전송한 호출의
늦은 응답은 사용량만 정산할 수 있으며 결과를 다시 활성화하지 못한다.

## Transition and acceptance

새 snapshot은 추가적인 nullable 저장 경계로 시작한다. 기존 원본·가입 사실·교정·과거
청구 snapshot을 재작성하지 않는다. 소스/지식/규칙 변경은 새 분석을 만들고 이전 결과를
stale로 표시한다. 전체 자료 backfill·generation 활성화·복원 수용은 WP09가 조립한다.

문서 원문의 현재 선택과 범위 처리 완료는 구분한다. 이전 current가 없고 유효한 원문 노드가
있는 첫 PARTIAL 구조는 독립적인 원문 anchor 검증을 위한 current가 될 수 있다. 미처리 범위와
PARTIAL 상태는 유지하며, 기존 current가 있는 경우 부분 재처리가 이를 교체하지 않는다.
빈 원문·취소된 구조는 활성화하지 않는다. Metadata의 역할/필드 검증과 가입·규칙의 별도
검증을 생략하지 않으며, source availability v4는 과거 준비 이력을 수정하지 않고 한 번 재검증한다.

B01부터 합성 문서 기준 정답집, 개발/holdout 그룹, 전부 보류·전부 추천·무관 조건부 대조군을
사용한다. 후보 품질과 지원 범위·금액·근거·지연을 분리해 평가하며 부분 지원의 결과를
전체 자료 정확도로 표현하지 않는다. 목표/표본/환경 변경은 #60에 명시한다.

## Document component refinement

동일 DocumentVersion의 더 강한 원문 검증 결과는 미교정 `PROGRAM_VERIFIED` component의
현재 조회를 successor로 교체할 수 있다. 기존에 해결된 필드 값을 모두 보존하고, 새 필드 또는
더 넓은 검증 범위를 추가해야 한다. 증권·청약·변경 문서는 상품 일치만으로 범위를 확장하지
않는다. 사용자 결정·삭제·set 연결 이력이나 조항 이력이 하나라도 있으면 자동 교체를 보류한다.

`document_component_supersessions`는 이전/새 component와 publication, 새 약관 판본을
연결하는 불변 이력이다. 이전 component의 역할·범위·metadata와 TermsEdition은 보존하며,
이전 component에는 successor 식별자만 기록한다.
새 판본 등록 실패 시 교체 전체가 rollback되어 기존 판본이 계속 조회된다. 현재 문서·판본·
조항·규칙 조회는 successor를 따르며, 과거 snapshot의 식별자와 원문 근거는 유지한다.
동일 bytes의 재가져오기는 잠금을 공유하고, 별도 import의 기존 검토 이력을 자동 교체하지 않는다.

## Terms applicability provenance

계약의 실제 증권 페이지와 검증된 metadata에서 적용 판본을 연결한다. 명시적 적용 참조 또는
상품코드·실제 계약일·인쇄 기간을 보험사와 함께 대조하고, 일반 참조·판본일·유사 표시명만으로
확정하지 않는다. 보장 시작일에서 유래한 원장 날짜는 실제 계약일과 분리한다. 입력 변경·
사용자 결정·복수 판본 모호성은 현재 조회에 반영하고 기존 평가/청구 snapshot은 보존한다.
자동 적용과 수동 선택의 출처는 다르게 표시한다. 적용 연결은 계약 유지 상태·가입 특약·
지급 조건을 새로 만들지 않는다. 세부 계약은 [조항 연결 설계](clause-linking-search.md)에 있다.

변경/갱신 원문은 기존 계약번호 근거·보험사·로컬 피보험자와 실제 가입 담보의 원문 이름을
대조한다. 표시명 교정은 원래 담보 identity를 지우지 않으며 원문 연결·상품 교정은 보존한다.
`policy_terms_changes`는 적용 범위, 교체/추가, 명시 적용일, 이전/새 판본과 원문 span·입력
revision/digest를 불변 이력으로 저장한다. 신규 가입이나 active 상태는 만들지 않는다.
선택기는 사건일과 계약/담보/조항 범위를 사용하며 명시 종료일 밖에서는 독립된 기존 판본
판정을 유지한다. 새 판본/날짜가 불완전하면 알려진 관련 대상만 불확실하게 남기며 다른
담보를 교체하지 않는다. 미해결 담보·조항을 계약 전체 범위로 바꾸지 않는다.
조항 범위는 변경서의 이전/새 라벨, 판본, 실제 가입 담보와 독립 검증된 전체 조항 원문을
대조하여 양쪽 원래 Clause ID와 출처 평가를 연결한다. 저장된 MATCH만으로 게시를 허용하지
않고 변경서 원문과 대상 근거를 다시 읽는다. 정확한 새 대상의 링크 확인·규칙 게시만
허용하며 사건일 적용은 별도로 선택한다. 양쪽 연결을 따라 후속 변경을 조회하되 인접 조항은
포함하지 않는다. 상위 조항 변경은 아직 대응을 확인하지 못한 하위 항에 불확실성으로 남긴다.
근거 상실은 이전 연결 이력을 지우지 않으며 새 분석에서 관련 범위만 UNKNOWN으로 처리한다.

`decision-engine-v2`의 규칙 reader는 구성원과 사건일을 명시적으로 받는다. 판본의 `NO_MATCH`
규칙은 해당 사건의 평가에서 제외하고, `UNKNOWN` 규칙은 사실/근거와 불확실성 이유를 남긴다.
필수 규칙의 불확실성을 다른 규칙의 성공으로 지우지 않으며 optional 규칙의 기존 의미를
유지한다. 범위나 사건일이 다른 선택이 섞이면 해당 담보의 선택 metadata 전체를 폐기한다.

`decision_runs.terms_selections_json`은 기본 판본 평가 ID, 적용/미해결 변경 관계 ID와
담보/조항별 선택·사건일을 보존한다. 문서/원장/사건 교정은 이를 수정하지 않는다. 이전 run의
null과 새 run의 빈 선택을 구분하며, 없는 과거 선택을 재구성하지 않는다. DB는 정확한
가정·구성원·계약·담보·조항·사건 버전과 출처 ID 범위를 검증하고 선택 수정은 거부한다.
같은 run의 `source_rule_version_ids`에는 유효한 선택과 함께 실제 읽은 규칙 버전을 고정한다.
선택 또는 규칙 참조를 보존한 run이 있으면 migration downgrade는 이력을 지우기 전에 거부한다.

계산은 같은 run에 저장된 선택·규칙 ID와 `published_at <= run.created_at`을 각각 확인한다.
분석 전에 게시 시각을 기록했지만 분석 중에 commit한 규칙도 과거 조회에 끼워 넣지 않는다.
한 산식의 적용이 불확실하면 `TERMS_APPLICABILITY_UNRESOLVED`와 금액 미확정을 저장한다.
원문 evidence의 기존 무결성 검사는 유지한다. 여러 가능한 산식의 결과 구성은 B03/B06의
후속 범위이며 현재 단일 산식 경계를 임의의 한 판본 선택으로 우회하지 않는다.
