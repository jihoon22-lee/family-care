## 방법과 실제 전송

합성 원문→PostgreSQL→로컬 약관 해석→안내→실제 SDK/Worker→원문 검증→API 결과를
평가했다. 정답은 채점 단계에서만 사용했다. 개발·holdout의 가까운 표현으로 표본을 늘리거나
실패 사례를 제외하지 않았다. 원래 메모리 benchmark와 companion 원문 adapter의 계산
지원 범위는 별개다.

`gpt-5.6-terra`, Standard tier, 텍스트 요청, 최대 출력 4,000 tokens, SDK 재시도 0,
요청 40초 제한을 사용했다. 총 USD 1 상한 아래 각 사례를 한 번만 예약했다. 실제 HTTP
요청·응답은 각각 20건이며 20건 모두 사용량이 확인돼 정산됐다. 재호출하지 않았다.

## 실패와 원문 범위

`synthetic-dev-historical`, `synthetic-holdout-two-contracts`는
`REVIEW_INVALID_RESPONSE`, `synthetic-holdout-missing-cost`는 `REVIEW_INCOMPLETE`로
종료됐다. 세 사례 모두 로컬 결과가 보존됐다. 남은 17개 결과는 disagreement 16 / partial 1이다.

전체 20건의 준비된 packet은 45개다. 저장 결과가 있는 17건은 36개 packet을 보고하며,
실패 3건의 9개 packet은 성공 분모로 옮기지 않는다. 17건의 예상 원문 region 144개 중
공급 36 / 미공급 108이어서 범위는 PARTIAL이다. 결과 내 packet 미검수/누락 0이라는
수치는 모든 원문 region이나 실패 3건까지 검수했다는 뜻이 아니다.

사용량·원문 요청·응답·예약 이력은 저장소 밖 제한된 합성 평가 기록에 보존했다.

판독의 미지원 형식·실제 자료 전체 계산·모바일 PWA 수용은 이 평가로 완료되지 않는다.
