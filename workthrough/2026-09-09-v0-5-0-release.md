# v0.5 release and deployment workthrough

v0.5.2의 GitHub Release 게시와 승인된 WSL 전환·재시작 검증을 완료했다. 실행 소스는
`2370761613f33e833cf9e86f55cff1cedfc3e1e6`/0069이며 원본 0024 DB를 보존했다.
자동 노트 생성 실패는 검증된 이미지의 수동 메타데이터 게시로 복구했다. 자동 workflow
전체 PASS나 마일스톤 전체 완료로 표시하지 않는다. 아래 초기 미실행 표현은 당시 기록이며
최종 결과는 마지막 절과 수용 원장을 따른다.

통합된 로컬 청구 안내·보관 원문 재처리의 제품 버전을 0.5.0으로 맞추고, 실제 실행한 수용과
미지원 범위를 현재 문서에 연결했다. API/Worker pyproject와 runtime 버전, Web package,
uv.lock, OpenAPI health/default, health 테스트와 CHANGELOG를 함께 변경했다. 생성 Web
계약은 재생성했으며 타입 내용의 추가 변경은 없었다.

README·보안/구조 문서·로드맵과 B07/B08·수용 원장은 현재 코드와 과거 실행을 구분한다.
전체 자료의 자동 해석은 PARTIAL이며 자동 약관 판본/의미 지식, 읽지 못한 자료와 정확한
과거 별칭 연결을 성공으로 집계하지 않는다. 실제 값·개수·경로·식별자는 공개하지 않는다.

release의 통합 step에 `${{ job.services.postgres.id }}`를 전달하고, CI와 release 양쪽에서
이 복원 컨테이너 바인딩이 빠지면 정책 검사가 거부하도록 했다. 회귀는 **2 failed/22 passed**로

확인했다. 실패한 도구 실행에서 만든 clone 합성 관리자 세션만 시간·사용자 범위로 확인해
