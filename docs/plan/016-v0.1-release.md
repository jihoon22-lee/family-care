**Goal**

모든 v0.1 기능 PR이 merge된 뒤 Web, API, Worker 세 이미지를 v0.1.0으로 재현 가능하게 검증하고 GHCR에 게시할 준비를 한다. 이 계획의 구현 PR은 release metadata, workflow policy, digest evidence, private Compose smoke 경계를 준비한다. 실제 Git tag 생성과 push는 모든 선행 PR의 merge 및 Root PR gate 통과 후 root agent가 별도 단계로 수행한다. GHCR 게시 성공은 운영 배포를 뜻하지 않으며 Cloud Run은 이 릴리스 범위에 없다.

**Architecture**

- release workflow는 vMAJOR.MINOR.PATCH tag push에만 실행되고 validate-tag와 validate-foundation이 모두 성공한 뒤 publish job을 시작한다.
- validate-foundation은 synthetic PostgreSQL·synthetic fixtures·고정된 action SHA·전체 Python/Web/contract/container 검사를 실행하고 세 이미지를 push=false로 한 번씩 빌드한다.
- publish는 matrix의 web, api, worker 세 항목만 처리하고 GHCR에 version tag와 commit SHA tag를 게시한다. latest tag는 만들지 않는다.
- packages: write 권한은 publish job에만 둔다. CI와 pull_request job에는 비밀값과 packages: write를 부여하지 않는다.
- publish 후 검증은 세 이미지의 OCI manifest digest를 받아 tag가 가리키는 digest와 commit SHA tag가 가리키는 digest를 비교한다. 이미지 파일 시스템과 private data를 export하지 않는다.
- verify-publication 성공 후 최종 publish-release job이 같은 digest를 다시 검증한다. 이 job만
  contents: write를 사용하고, 두 검증 job만 packages: read를 사용한다.
- GitHub Release 변경사항은 태그 checkout의 CHANGELOG 해당 버전 섹션을 단일 원본으로 삼는다.
  검증된 workflow·commit·세 이미지 digest만 별도 증거로 덧붙인다.
- Release 본문은 mode-0600 새 Markdown 파일에 렌더링하고 gh release create 또는 edit의
  --notes-file로만 전달한다. 인라인 본문과 문자 그대로의 역슬래시-n은 허용하지 않는다.
- private Compose smoke는 외부 host에 API·DB·Worker 포트를 열지 않고 Web gateway health와 synthetic authenticated route만 확인한다. 실제 문서·실제 key·실제 Tailscale 상태를 CI 증거로 만들지 않는다.
- 릴리스 문서는 결과와 미검증 경계를 기록한다. 실제 Windows, mobile PWA, 기존 Tailscale, 실제 insurance PDF, 운영 환경은 별도 검증으로 남긴다.

**Tech Stack**

- GitHub Actions with immutable full commit SHA action references
- Docker Buildx, Docker Compose v2, OCI Distribution manifest API
- GHCR image names derived from GITHUB_REPOSITORY with suffixes -web, -api, and -worker
- Python 3.14 scripts using urllib, json, dataclasses, and existing pytest
- existing Web/API/Worker Dockerfiles and pinned base images
- PostgreSQL 18 synthetic integration service
- Conventional Commits, annotated v0.1.0 Git tag, and release evidence Markdown

각 Task와 최종 릴리스 단계에서 다음 규칙을 모두 확인한다.

- 실제 보험증권·약관·의료문서, 추출 텍스트·표·스크린샷·페이지 이미지·OCR·embedding을 저장소·CI·GHCR image layer·release artifact에 넣지 않는다.
- 실제 이름·이메일·주소·전화번호·생년월일·증권번호·금액·Drive 식별자를 코드·fixture·로그·release evidence에 기록하지 않는다. 모든 샘플은 Admin A, Family Member A, Sample Policy, synthetic-policy-001처럼 처음부터 합성한다.
- CI와 release foundation은 실제 문서·실제 password·실제 master key·Google Drive·외부 AI 없이 실행한다. 외부 AI adapter는 synthetic candidate와 deterministic verifier stub으로 검사한다.
- AI는 구조화와 설명을 보조할 뿐 보험 자격 판정·계산·권한 부여의 권위자가 아니다. 계약 상태·문서 근거가 없으면 결과는 UNKNOWN이며, release 또는 container failure를 MATCH/NO_MATCH로 바꾸지 않는다.
- Phase 1의 /health/live, /health/ready, /api/v1/documents/{document_id}/analysis, document-ingestion.v1, extraction-result.v1, analysis-job.v1, source_key 상대경로, PASSWORD_REQUIRED, lease 및 retry semantics를 보존한다.
- Web Storage와 service worker에는 PDF·보험 데이터·API response·session token을 넣지 않는다. release log와 evidence에는 문서 본문·검색어·개인식별자·인증 token·실제 경로를 기록하지 않는다.
- release tag, tag push, GHCR publish, image deletion, registry cleanup, production deployment는 선행 merge와 root approval 없이 수행하지 않는다. 이 계획의 구현 단계는 local/CI policy와 evidence 도구만 만든다.
- Cloud Run, gcloud, Kubernetes, SSH deployment, public ingress, database migration against a production system은 이 계획에서 생성·호출하지 않는다.
- 기존 Compose stack, 다른 프로젝트의 process·container·volume·port, 기존 Tailscale 설정을 중지·변경·삭제하지 않는다. private smoke 전 ownership을 read-only로 확인하고 충돌하면 중단한다.

### Release interfaces

Create scripts/release_audit.py with the following stable Python interface:

~~~python
from dataclasses import dataclass
from pathlib import Path
from typing import Literal


@dataclass(frozen=True)
class ReleaseIdentity:
    version: str
    tag: str
    commit_sha: str
    image_names: tuple[str, str, str]


@dataclass(frozen=True)
class ReleaseFinding:
    code: str
    detail: str


@dataclass(frozen=True)
class ReleaseImageDigest:
    component: str
    digest: str


def check_release_identity(
    repository_root: Path,
    version: str,
    commit_sha: str,
) -> tuple[ReleaseFinding, ...]:
    """Check package versions, tag shape, and the three image names."""


def verify_image_digests(
    registry: str,
    repository: str,
    version: str,
    commit_sha: str,
    http_get: callable,
) -> tuple[ReleaseFinding, ...]:
    """Compare OCI manifest digests for version and commit tags."""


def inspect_image_digests(
    registry: str,
    repository: str,
    version: str,
    commit_sha: str,
    http_get: callable,
) -> tuple[tuple[ReleaseImageDigest, ...], tuple[ReleaseFinding, ...]]:
    """Return ordered web/api/worker digests only after complete verification."""
~~~

The HTTP contract for verify_image_digests is:

- Request method: GET, with no request body.
- URL: https://ghcr.io/v2/REPOSITORY-web/manifests/0.1.0, then the corresponding api and worker URLs. The repository path is supplied by the caller; no real owner or repository value is written into fixtures.
- Accept header: application/vnd.oci.image.index.v1+json, application/vnd.docker.distribution.manifest.list.v2+json, application/vnd.oci.image.manifest.v1+json, and application/vnd.docker.distribution.manifest.v2+json.
- Required response: status 200 and a valid Docker-Content-Digest header. A response body is parsed only for child manifest platform count; layer contents are never downloaded.
- Repeat for the commit SHA tag. The evidence is valid only when each version-tag digest equals its same-image commit-tag digest. A missing, mutable, or cross-image digest is a failure category.

The Compose smoke interface is:

~~~yaml
services:
  web:
    image: ghcr.io/${GITHUB_REPOSITORY}-web:0.1.0
  api:
    image: ghcr.io/${GITHUB_REPOSITORY}-api:0.1.0
  worker:
    image: ghcr.io/${GITHUB_REPOSITORY}-worker:0.1.0
~~~

The smoke runner must execute a temporary override outside the repository:

    docker compose --env-file .env.example -f infra/compose/compose.yaml -f RUNTIME_OVERRIDE config
    docker compose --env-file .env.example -f infra/compose/compose.yaml -f RUNTIME_OVERRIDE up --detach
    curl --fail --silent --show-error http://127.0.0.1:FAMILYCARE_WEB_PORT/healthz

RUNTIME_OVERRIDE is generated from verified digests in a per-run temporary directory and removed on success, failure, and cancellation. It must not contain a password, key, document content, or user path in evidence.

### Root PR gate and handoff

Before the root agent opens the PR for this plan, root must review the whole diff once and run the plan's focused tests, then run the shared Root PR gate in docs/plan/003-v0.1-implementation-index.md. The gate must confirm:

- all package and runtime versions agree on 0.1.0 without changing Phase 1 contracts;
- synthetic CI and release-foundation checks pass without external AI or private documents;
- the workflow has semantic tag trigger, immutable action SHAs, validation before login/publish, exactly three images, no latest, and packages: write only on publish;
- the digest verifier and post-publication procedure require Web/API/Worker version and commit tags to resolve to equal per-image OCI digests; actual equality is a post-tag release condition, not a pre-tag gate claim;
- private Compose smoke exposes only Web and preserves Worker-only key access;
- /healthz and the approved authenticated HTTP surface are no-store and do not disclose data;
- release evidence records pass, failed, and unverified separately;
- no Cloud Run, production deployment, release-time Tailscale mutation, unrelated process/container change, or unapproved real-document inspection occurred.

The final release report includes the PR URL, merge commit, workflow run, three image references and digests, tag status, GHCR status, exact commands and results, security/privacy boundary, and every unverified acceptance item. A successful GHCR publication does not claim a production deployment.
